## Le projet
Site **ClutchCrosshair.com** : les codes de crosshair CS2 des joueurs pros et des créateurs de contenu.
Pour chaque joueur : photo, équipe, aperçu du crosshair, code de partage + commandes console, bouton Copy.
Objectifs : très fluide et ergonomique, design 2026, bon référencement Google (mot-clé « CS2 »), monétisation plus tard. Valorant plus tard.

Hébergement : **Cloudflare Pages — https://clutchcrosshair.com** (depuis le 19/10/2026 ; adresse officielle SANS www ; le code reste sur GitHub, chaque push est mis en ligne par Cloudflare). Ancienne adresse GitHub Pages **désactivée le 19/10/2026** (404). www → sans www : règle de redirection Cloudflare 301 (modèle « Redirect from WWW to root »), vérifiée.
**Cloudflare sert les pages sans « .html »** (/players/zywoo.html → redirection 308 vers /players/zywoo, /tools/index.html → /tools/) : build.js retire donc « .html » de toutes les adresses ABSOLUES (canonical, sitemap, og:url, JSON-LD) à la fin du build (`absoluteHtml`). Les liens internes relatifs gardent « .html » (Live Server). `SITE_URL` = https://clutchcrosshair.com en haut de build.js. Fichier **`_headers`** (Cloudflare) : `noindex` sur l'adresse technique *.pages.dev + **cache navigateur 1 an `immutable`** pour le CSS/JS, les polices, les photos, les logos, les images des skins et les fonds des aperçus (lib/ : 30 jours). **Tout ce qui est gardé 1 an doit être appelé avec une empreinte `?v=`** (build.js le fait : `versioned()` pour les photos et logos, empreintes des fonds écrites dans crosshair.js) ; les images des skins ont un nom tiré de leur contenu. Nouveau fichier JS/image → l'ajouter dans `_headers` ET lui donner une empreinte dans build.js.

**Optimisations Lighthouse (20/10/2026)** — mesures locales, accueil mobile : performance 97 → **99**, LCP 2,4 s → **1,9 s**, poids 327 → **226 Ko** ; page joueur 100. (En ligne, le « Legacy JavaScript » vient du script Cloudflare Web Analytics : à ignorer.)

## Les codes de crosshair CS2 (important)
Depuis la mise à jour CS2 du 30/09/2026, les codes sont au nouveau format **`CS...`** (sans tirets, ex. `CSH2Rx7cGRU5apQ4VSnZwjsr9RyLEiOrCAaVYWYvW6dz7H`).
Les anciens `CSGO-xxxxx-...` ne s'importent plus dans le jeu → **ne jamais mettre de code `CSGO-` sur le site**, et ne pas lire de démo d'avant le 30/09.
Les listes de codes trouvées sur Internet sont presque toutes encore en `CSGO-` : inutilisables.
`csgo-sharecode` 7.0.1 décode les deux (champ `format` : `cs2-v1`, `legacy-v1`…). Dans le nouveau format, les tailles sont en pixels pour `screenHeight`.
**`cl_crosshairstyle 9` = crosshair en X** (4 traits en diagonale + point droit), vu en jeu par Anto sur shox le 19/10/2026 : dessiné à part dans `drawCrosshair` (crosshair.js), réglé au pixel sur sa capture en 1280×960 (4 petits carrés de côté = épaisseur arrondie vers le bas). Les autres styles (3, 4, 5) sont dessinés en « + » classique.
Plusieurs pros ont exactement le même code (ex. petit crosshair cyan ou vert) : c'est normal, vérifié en décodant (peu de réglages possibles en pixels) et **revérifié le 19/10/2026 en relisant les 8 démos** (chaque joueur garde un seul code par match, le site a bien le plus récent ; 60 codes différents pour 70 pros, 50 pros ont une longueur 2). Petite ligne grise **« Same crosshair as … »** sous l'aperçu (`.same-xhair`) : pages joueurs (vrais liens, fonction `twins()` dans build.js) et fiche (`data-twins` sur la carte, liens `#pseudo` qui ouvrent la fiche de l'autre joueur, `#modal-same` dans script.js) ; absente si le code est unique.

## Le robot read_demo.py
- Lit une démo CS2 (.dem) avec `demoparser2` (`pip install demoparser2`, déjà installé).
- Récupère pour chaque joueur : pseudo, SteamID, équipe (dernier `team_clan_name` **non vide** — parfois vide en fin de match), crosshair (`crosshair_code`, constant pendant tout le match).
- Met à jour `players.json` : ajoute les nouveaux joueurs, met à jour les codes, suit les transferts par SteamID. Ignore les équipes qui ne sont pas sur le site (liste `SITE_TEAMS` + `TEAM_ALIASES`).
- **`updated` = date du match** (date du fichier .dem, conservée dans l'archive HLTV ; sinon `--date JJ/MM/AAAA`). Même code → la date avance (crosshair confirmé).
- Une démo **plus ancienne** que la date enregistrée ne change rien (plus besoin de lire dans l'ordre). Démos d'avant le 30/09/2026 et codes `CSGO-` refusés.
- Utilisation : `py read_demo.py "demos/fichier.dem"` (ou `--date 16/10/2026`) puis `node build.js`.
- Les démos viennent de HLTV (je les télécharge à la main, souvent en `.rar` dans Téléchargements ; une seule map suffit). Le `tar` de Windows (`C:\Windows\System32\tar.exe -xf archive.rar`) sait les ouvrir. **HLTV bloque les robots (Cloudflare) : ne pas essayer de contourner.**
- Démos déjà lues (dates corrigées le 18/10/2026 ; Spirit/Vitality/MOUZ gardent 17/10, leurs démos ne sont plus là) : FURIA-Aurora, Falcons-BetBoom, BetBoom-Legacy, G2-PARIVISION, PARIVISION-NAVI, FaZe-NAVI Junior, Astralis-MIBR (+ Spirit, Vitality, MOUZ avant). 71 joueurs, 14 équipes sur 15.
