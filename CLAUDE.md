## Le projet
Site **ClutchCrosshair.com** : les codes de crosshair CS2 des joueurs pros et des créateurs de contenu.
Pour chaque joueur : photo, équipe, aperçu du crosshair, code de partage + commandes console, bouton Copy.
Objectifs : très fluide et ergonomique, design 2026, bon référencement Google (mot-clé « CS2 »), monétisation plus tard. Valorant plus tard.

Hébergement : **Cloudflare Pages — https://clutchcrosshair.com** (depuis le 19/10/2026 ; adresse officielle SANS www ; le code reste sur GitHub, chaque push est mis en ligne par Cloudflare). Ancienne adresse GitHub Pages **désactivée le 19/10/2026** (404). www → sans www : règle de redirection Cloudflare 301 (modèle « Redirect from WWW to root »), vérifiée.
**Cloudflare sert les pages sans « .html »** (/players/zywoo.html → redirection 308 vers /players/zywoo, /tools/index.html → /tools/) : build.js retire donc « .html » de toutes les adresses ABSOLUES (canonical, sitemap, og:url, JSON-LD) à la fin du build (`absoluteHtml`), **et aussi des liens internes relatifs depuis le 24/10/2026** (`relativeHtml` : href, data-legal, adresses du sélecteur de langue ; « donk.html » → « donk », « tools/index.html » → « tools/ ») pour que Google ne suive plus de redirections. Les sources gardent « .html », c'est le nettoyage final qui les retire. Test local : **`serve.js`** (imite Cloudflare : adresses sans .html, redirections 308, 404.html ; vérifié : 856 adresses internes répondent en 200 sans redirection). Sécurité (24/10/2026) : il refuse les demandes qui ne visent pas `127.0.0.1:5500` / `localhost:5500` (protection « DNS rebinding ») et ne sert jamais les fichiers cachés (`.env`, `.git`…), `csfloat-key.txt` ni `faceit-test/`. `SITE_URL` = https://clutchcrosshair.com en haut de build.js. Fichier **`_headers`** (Cloudflare) : `noindex` sur l'adresse technique *.pages.dev + **cache navigateur 1 an `immutable`** pour le CSS/JS, les polices, les photos, les logos, les images des skins et les fonds des aperçus (lib/ : 30 jours). **Tout ce qui est gardé 1 an doit être appelé avec une empreinte `?v=`** (build.js le fait : `versioned()` pour les photos et logos, empreintes des fonds écrites dans crosshair.js) ; les images des skins ont un nom tiré de leur contenu. Nouveau fichier JS/image → l'ajouter dans `_headers` ET lui donner une empreinte dans build.js.

## Les codes de crosshair CS2 (important)
Depuis la mise à jour CS2 du 30/09/2026, les codes sont au nouveau format **`CS...`** (sans tirets, ex. `CSH2Rx7cGRU5apQ4VSnZwjsr9RyLEiOrCAaVYWYvW6dz7H`).
Les anciens `CSGO-xxxxx-...` ne s'importent plus dans le jeu → **ne jamais mettre de code `CSGO-` sur le site**, et ne pas lire de démo d'avant le 30/09.
Les listes de codes trouvées sur Internet sont presque toutes encore en `CSGO-` : inutilisables.
`csgo-sharecode` 7.0.1 décode les deux (champ `format` : `cs2-v1`, `legacy-v1`…). Dans le nouveau format, les tailles sont en pixels pour `screenHeight`.
**`cl_crosshairstyle 9` = crosshair en X** (4 traits en diagonale + point droit), vu en jeu par Anto sur shox le 19/10/2026 : dessiné à part dans `drawCrosshair` (crosshair.js), réglé au pixel sur sa capture en 1280×960 (4 petits carrés de côté = épaisseur arrondie vers le bas). Les autres styles (3, 4, 5) sont dessinés en « + » classique.
**Placement des traits mesuré en jeu le 24/10/2026** (6 captures d'Anto en 1280×960 dont ZywOo, reproduites au pixel près par `drawBars` dans crosshair.js et `crosshairRects` dans og.js ; test : script `xhair-test.mjs`) : chaque trait commence à **« écart » pixels du centre de l'écran** (l'épaisseur ne change PAS sa place) ; épaisseur impaire = 1 px de plus à gauche/en haut ; longueur, épaisseur et écart = `round(valeur × hauteur d'écran / screenHeight)` en pixels du jeu, puis agrandis. L'ancien calcul (écart compté depuis le bord du trait = + moitié de l'épaisseur) laissait un trou en trop au centre. Piège : `cl_crosshair_screen_height` tapé en console n'a pas pris effet chez Anto (les captures restaient en 1080) ; une fausse règle « longueur − 1 » en était sortie le 24/10, corrigée grâce à ZywOo.
Plusieurs pros ont exactement le même code (ex. petit crosshair cyan ou vert) : c'est normal, vérifié en décodant (peu de réglages possibles en pixels) et **revérifié le 19/10/2026 en relisant les 8 démos** (chaque joueur garde un seul code par match, le site a bien le plus récent ; 60 codes différents pour 70 pros, 50 pros ont une longueur 2). Petite ligne grise **« Same crosshair as … »** sous l'aperçu (`.same-xhair`) : pages joueurs (vrais liens, fonction `twins()` dans build.js) et fiche (`data-twins` sur la carte, liens `#pseudo` qui ouvrent la fiche de l'autre joueur, `#modal-same` dans script.js) ; absente si le code est unique.
